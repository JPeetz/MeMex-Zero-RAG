## SECTION 1: iOS ARCHITECTURE (SwiftUI-First)

### 1.1 Technology Stack
- **Language:** Swift 6 with SwiftUI (primary), UIKit for calendar drag-and-drop edge cases
- **Minimum target:** iOS 17 (94% active devices per Apple June 2026 data)
- **Architecture:** MVVM with Observation framework (`@Observable` macro)
- **Persistence:** SwiftData for local models, CloudKit for multi-device sync (free at scale)
- **Health Data:** HealthKit read-only (heart rate, sleep, workouts, resting energy)
- **Calendar:** EventKit for read/write access to system calendar
- **Networking:** URLSession async/await, no third-party networking library
- **Analytics:** TelemetryDeck (privacy-first, no IDFA, GDPR-compliant)
- **Crash reporting:** Xcode Organizer + MetricKit (free, built-in)

### 1.2 Subscription Paywall (RevenueCat Integration)
- **SDK:** RevenueCat with custom SwiftUI paywall (NOT default)
- **Trigger:** After 3rd successful auto-scheduled day (user has experienced value)
- **Free tier:** Manual scheduling + basic energy tracking. Up to 7 days of energy history. Single calendar.
- **Premium ($7/month):** AI auto-scheduling, unlimited energy history, energy pattern insights, multi-calendar sync, priority support
- **Annual ($50/year):** 40% discount vs monthly. Pre-selected in paywall.
- **Lifetime ($120):** Power user option. 2-year break-even at monthly rate.
- **Trial:** 7-day free trial, no card required (RevenueCat allows this, lifts conversion 15-30%)

### 1.3 Screen-by-Screen Specification

**Screen 1: Onboarding (3 cards max)**
- Card 1: "You have a natural rhythm. 🎯" — Animation of energy wave throughout a day. Emotional hook: "Some hours you're unstoppable. Others, you're running on empty."

- Gesture: Pull down to see weekly view, long-press task to reschedule

## SECTION 5: VISUAL DESIGN SYSTEM

### 5.1 Design Principles
1. **Data as decoration.** The user's energy curve IS the UI. Chrome is minimal. The data is beautiful enough to stand alone.
2. **Motion with meaning.** Every animation communicates information. The energy wave doesn't just look cool — it shows time until next peak.
3. **Dark by default.** Energy visualization pops on dark backgrounds. Light mode is a toggle for accessibility.
4. **Privacy is premium.** Visual cues (lock icons, "processed on-device" badges) signal trust. Premium feel comes from safety, not flash.

### 5.2 Key Animations
- **App open:** Energy wave draws from left to right (0.8s, ease-out). Calendar fades in behind it (0.3s delay).
- **Task complete:** Circle check animates with spring (damping 0.5, 0.4s). Task card slides right and fades. Mini confetti (6 particles, 0.6s).
- **Energy zone transition:** Color gradient shifts smoothly over 2s when moving from peak to recovery zone.
- **Error state:** Gentle horizontal shake (0.3s) + amber border pulse. Auto-heals after 2s.
- **Empty → populated:** Staggered fade (0.05s delay per item). Cards scale from 0.95 to 1.0.

### 5.3 Haptic Feedback Map
- Light impact: Task completion, toggle switch
- Medium impact: Energy zone change, task reschedule
- Heavy impact: Day complete, 7-day streak, new energy insight unlocked
- Selection: Duration picker, energy requirement picker
- Notification: Only for "peak energy window starting" alert

### 5.4 Accessibility as Luxury
- **VoiceOver:** Energy curve announced as "Your energy peaks at 10 AM and declines after 3 PM." Tasks announced with energy context.
- **Dynamic Type:** All text scales to accessibility max. Energy curve labels reposition for readability.
- **Reduce Motion:** All decorative animations become instant. Energy curve still animates (functional, not decorative).
- **Color blindness:** Energy zones use pattern + color (dots for peak, dashes for recovery). Tested with protanopia, deuteranopia, tritanopia.

## SECTION 8: TECHNICAL SPECIFICATION

### 8.1 Database Schema (SwiftData / Room)

```sql
-- User profile
CREATE TABLE UserProfile (
  id TEXT PRIMARY KEY,
  chronotype TEXT,           -- 'early_bird', 'night_owl', 'intermediate'
  energySensitivity TEXT,    -- 'reactive', 'moderate', 'steady'
  createdAt INTEGER,
  premiumUntil INTEGER
);

-- Energy readings (from HealthKit / Health Connect)
CREATE TABLE EnergyReading (
  id TEXT PRIMARY KEY,
  timestamp INTEGER NOT NULL,
  heartRate REAL,
  hrv REAL,
  sleepQuality REAL,        -- 0-1 derived score
  energyScore REAL,         -- 0-100 computed
  zone TEXT,                -- 'peak', 'recovery', 'focus', 'low'
  source TEXT               -- 'apple_watch', 'manual', 'predicted'
);
CREATE INDEX idx_energy_timestamp ON EnergyReading(timestamp);

-- Scheduled tasks
CREATE TABLE Task (
  id TEXT PRIMARY KEY,
  title TEXT NOT NULL,
  durationMinutes INTEGER,
  energyRequirement TEXT,   -- 'high', 'medium', 'low'
  scheduledStart INTEGER,
  scheduledEnd INTEGER,
  actualStart INTEGER,
  actualEnd INTEGER,
  completed INTEGER DEFAULT 0,
  calendarEventId TEXT,
  isAIScheduled INTEGER DEFAULT 0
);

-- Daily summaries
CREATE TABLE DaySummary (
  id TEXT PRIMARY KEY,
  date TEXT NOT NULL UNIQUE,
  peakWindowStart TEXT,
  peakWindowEnd TEXT,
  tasksCompleted INTEGER,
  tasksRescheduled INTEGER,
  peakZoneMinutes INTEGER,
  userRating INTEGER         -- 1-5 daily self-rating
);
```

**Cloud sync:** SwiftData + CloudKit (iOS). Room + Firebase Firestore (Android). Energy data stays on-device; task data syncs.

### 8.2 API Endpoints (Minimal Backend)

Only needed for cross-platform sync and sharing. Local-first architecture means most functionality works offline.

```
POST /api/v1/tasks/sync          — Sync task state across devices
GET  /api/v1/insights/weekly     — Weekly energy summary (computed on-device, backed up)
POST /api/v1/share/card          — Generate shareable energy profile card URL
GET  /api/v1/user/profile        — Retrieve synced profile
PATCH /api/v1/user/profile       — Update chronotype, preferences
```

Auth: Sign in with Apple (iOS) / Google (Android). JWT + refresh tokens.

### 8.4 AI Agent Architecture (Local-First)

**Energy Prediction Model:**
- On-device CoreML model (iOS) / TensorFlow Lite (Android)
- Inputs: 7-day heart rate, HRV, sleep duration/quality, historical energy scores, day of week, time of day
- Output: 24-hour energy curve (hourly energy score 0-100)
- Initial model: LSTM or lightweight transformer (~2MB). Trained on synthetic data initially, fine-tuned per-user on-device.
- Update: Nightly retraining using user's accumulated data. Gets better with use.

**AI Scheduling Agent (ReAct Pattern):**
```
User adds task "Write proposal" (high energy, 90 min)
→ LLM receives: [task, energy profile, calendar state, rules: "high energy tasks → peak window"]
→ LLM decides: tool_call("schedule_task", {task_id, start: 10:00, end: 11:30})
→ Tool executes: writes to calendar, returns confirmation
→ LLM outputs: "I've scheduled 'Write proposal' from 10:00-11:30 — your peak window. This leaves your 2pm recovery window free."
```

**Model:** Phi-4-mini (3.8B Q4, ~2.2GB). On-device via llama.cpp Swift bindings. Metal-accelerated. Latency <3s for scheduling decisions.

**Why on-device:** Calendar + health data is extremely sensitive. ZERO data leaves the device for AI processing. This IS the privacy moat.

## SECTION 12: ANTI-PATTERNS

1. ❌ **Do not ask for notification permission on first open.** 60% say no. Ask after first completed day, with pre-permission explaining value.
2. ❌ **Do not require account creation.** "Try before you sign up." Sign in with Apple/Google only when syncing or sharing.
3. ❌ **Do not use default RevenueCat paywall.** 40% conversion penalty. Custom SwiftUI/Compose paywall only.
4. ❌ **Do not ship with a static splash screen.** Instant animation into home. Skeleton UI if loading is necessary.
5. ❌ **Do not ship cloud AI first.** Health + calendar data leaving the device is a PR disaster waiting to happen. On-device AI is the privacy moat AND the differentiator.
6. ❌ **Do not ignore 1-star reviews.** Reply within 24 hours. Developer responsiveness boosts search ranking.
7. ❌ **Do not localize poorly.** Launch in English only. Add Spanish + German when you can afford human translation.
8. ❌ **Do not ship Android day-and-date with iOS.** iOS first. Learn from App Store review, then launch Android 2 weeks later.
9. ❌ **Do not add ads in the first year.** Ads destroy the premium feel. Monetize through subscription only.
10. ❌ **Do not make energy prediction feel rigid.** Users rebel against "your energy is low, you can't work." Frame as suggestion, not command. "We recommend a break — but you're the boss."
